# dl-1 — Resolver registry, manifest parsers, yt-dlp fast path

**Package:** `tools/downloader/resolvers` · **Was:** WP-1 · **Ran parallel with:**
[dl-2](./dl-2-browser-sniffer.md), [dl-3](./dl-3-download-engine.md),
[dl-4](./dl-4-web-ui.md)

## Why

The registry is what makes "first usable answer wins" a structure rather than a
sentence, and the parsers are what [dl-2](./dl-2-browser-sniffer.md) hands a
master playlist to once it has caught one. The yt-dlp tier is a **latency
optimisation, not a coverage mechanism**: it must be droppable without reducing
which sites work, which is why [02-ROADMAP.md](../02-ROADMAP.md) makes its
absence a fallthrough rather than an error.

## Build

The registry (1) and manifest parsers (4) are load-bearing — dl-2 consumes the
parsers. The yt-dlp adapter (2) must be droppable without reducing which sites
work. Build it last of the four, and if you run short of time, ship without it.

1. `registry.ts` — holds `Resolver[]` sorted by ascending `priority`. `resolve()`
   filters by `canHandle(url)`, tries each in order, and returns the first
   success. On `NO_MEDIA_FOUND` continue to the next; on **any other**
   `AppError` stop immediately and rethrow — `DRM_PROTECTED` and `AUTH_REQUIRED`
   are facts about the source, so retrying another technique only wastes time.
   Enforce `options.timeoutMs` across the whole chain via `AbortSignal`.

2. `resolvers/ytdlp.ts` — priority 20. Spawn
   `yt-dlp --dump-single-json --no-warnings --no-playlist <url>`, using an
   argument array and never `shell: true`. Map the JSON `formats[]` to
   `MediaVariant[]`: `format_id`→`id`, `vcodec`/`acodec` (`"none"` means absent),
   `filesize` vs `filesize_approx` (set `filesizeIsEstimate` accordingly),
   `protocol` (`m3u8*`→`hls`, `http_dash*`→`dash`, `https`/`http`→`progressive`).
   Copy `http_headers` into `RequestContext.headers`. Map `is_live`. Map
   `subtitles` + `automatic_captions` with `autoGenerated` set correctly.
   **If the `yt-dlp` binary is missing, `canHandle` returns false** — a missing
   binary is a fallthrough to the sniffer, never an error. Detect it once at
   construction, not per call. Honour `ENABLE_YTDLP_RESOLVER=false` the same way.
   Ship a test that runs the registry with this resolver disabled and asserts
   resolution still succeeds via the next tier.

3. `resolvers/direct.ts` — priority 90. When the URL itself is a manifest or a
   media file. `HEAD` it, branch on `Content-Type` (`mpegurl`→HLS,
   `dash+xml`→DASH, `video/*`→progressive), and for HLS/DASH fetch and parse the
   manifest to enumerate variants.

4. `manifest/hls.ts` and `manifest/dash.ts` — pure parsers, no I/O, heavily
   tested. HLS: `EXT-X-STREAM-INF` attributes, `EXT-X-MEDIA` audio groups,
   `EXT-X-KEY` (distinguish AES-128 from FairPlay/Widevine `KEYFORMAT`),
   `EXT-X-ENDLIST` for live detection. DASH: `AdaptationSet`/`Representation`,
   `SegmentTemplate` `$Number$`/`$Time$`, `ContentProtection` UUIDs.
   **These parsers are the DRM detectors** — get §3 of the analysis exactly right.

Fixtures: check in real master playlists and MPDs (multi-bitrate, split-audio,
AES-128, live, Widevine-protected) under `test/fixtures/`. Parse tests offline.

## Done when

A fixture-driven test suite covers every variant shape above, and DRM fixtures
produce `drm.protected === true` with the right system named.

## Log

Shipped in `5662f95`, in Phase 1's parallel block.

The expendability rule is asserted rather than trusted, though the assertion
arrived with [dl-5](./dl-5-api-and-orchestration.md) since nothing composed the
registry until then: `tools/downloader/api/test/queue-and-shutdown.test.ts` runs
with `ENABLE_YTDLP_RESOLVER=false` and the chain still contains the sniffer and
still resolves. A configuration with _every_ tier disabled is refused at boot —
answering `NO_MEDIA_FOUND` for every URL on earth is a misconfiguration, not a
result.

The ClearKey boundary the parsers implement was settled later, in dl-5's log:
HLS `KEYFORMAT="org.w3.clearkey"` with a directly fetchable key URI is transport
encryption and stays in scope; anything needing an EME licence exchange is a
hard stop.
